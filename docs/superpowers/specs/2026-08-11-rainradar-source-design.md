# Дизайн: смена источника радарных данных на rainradar.ru

Дата: 2026-08-11
Статус: принято (решение по палитре — оригинальная rainradar)

## Контекст / Проблема

Наша карта радара (`radar.html`) берёт осадки с RainViewer (`api.rainviewer.com` / `tilecache.rainviewer.com`). По замерам источник недооценивает осадки над Россией в 2.5–4.5 раза (Тверь: 420 против 1145 пикселей rainradar; Гомель–Смоленск: 53 против 237). Пользователь подтвердил: фронт «Гомель → север до Петрозаводска и дальше» на нашей карте практически не виден.

Рассмотренный альтернативный источник — Weather & Radar (WetterOnline, `tiles.wo-cloud.com`), разобран APK v2026.16.1:
- эндпоинты `/data?path=` → 403, тайловый `/?tiles=…&k=…` → 401, сайт отдаёт 403 ботам (headless-браузер видит пустую страницу);
- даже metadata-конфиги отдают только конфигурацию, сами тайлы требуют авторизации;
- **вывод: источник недоступен для стороннего использования**, включая слой молний.

**Решение: перейти на rainradar.ru** — единственный проверенный рабочий источник с полным доступом (CORS `*`, открытый manifest и тайлы) и данными по РФ включая облачность, осадки, грозы/град (в кодировке значений пикселей).

## Проверенные факты об источнике (реверс-инжиниринг)

### Manifest
`GET https://rainradar.ru/composite/manifest.json?{unix_сек}`

Формат (массив кадров, сортирован по времени возрастания):
```
[ [ts, [z3_tiles, z4_tiles, z5_tiles]], ... ]
```
- `ts` — unix-секунды (шаг 10 мин, количество кадров ≈ 13 — уточнить при реверсе);
- каждая группа `zK_tiles` — массив `[x, y]` пар тайлов, для которых есть данные на datazoom `K`;
- тайлы отсутствуют на территории без покрытия радаров (манифест — единственный источник истины о наличии данных).

### Тайл данных
`GET https://rainradar.ru/composite/{ts}/{dz}/{x}_{y}.png`
- PNG 264×264, кодирует интенсивность в красном канале (значение 0..~70, байты других каналов игнорировать);
- `dz` — datazoom: `view_zoom > 7 ? 5 : view_zoom > 5 ? 4 : 3` (`__getDataZoom`);
- группа в манифесте: `dz - 3` (индекс 0, 1, 2) — объект `{"x|y":1}` по парам `[x,y]`;
- тайл 264×264: центральные 256×256 соответствуют обычному XYZ-тайлу `(x, y, dz)`, 4 px с каждой стороны — запас для интерполяции;
- **scale** = `Math.pow(2, dz - view_zoom)` (для view z>dz — даунсемплинг, scale<1);
- **data-координаты тайла**: `dataX = Math.floor(view_x * scale)`, `dataY = Math.floor(view_y * scale)`.

### Палитра (оригинал rainradar.ru, `Pallete.colors`)
Значение → RGBA (alpha: 0 прозрачный, 0.8 полупрозрачный, 1 непрозрачный):
```
0  -> (146,163,185, 0.0)   прозрачный (нет данных)
1  -> (146,161,181, 0.8)   облачность
5  -> (103,104,158, 1.0)
11 -> ( 56, 64,128, 1.0)
15 -> ( 29,175, 87, 1.0)   зелёный (осадки)
30 -> (255,247,  0, 1.0)   жёлтый
40 -> (255,174,  0, 1.0)   оранжевый
47 -> (226, 40, 86, 1.0)   красный
58 -> (169, 10,158, 1.0)   фиолетовый (гроза/град)
60 -> (169, 10,158, 1.0)   упор до конца шкалы
```
Градиент строится линейно между стопами по осям «значение → цвет», шкала значений `0..70`.

### Интерполяция 264→256 (worker `renderTileSingle.js`)
Для каждого пикселя `(m,h)` view-тайла 256×256 бикубическая интерполяция по 4×4 соседям из raw-массива 264×264 (офсет +3, т.е. центрировано), результат `v`; цвет = палитра по `round(v/70*num_shades)`, где `num_shades = 700`. Пиксели с `v <= 0` прозрачны.

## Целевая архитектура

Только меняется источник данных внутри `radar_template.html` (собирается в `radar.html` через `tools/build_radar.py`). UI (таймлайн, play, легенда, зум, OSM-подложка) не меняется.

### Компоненты

1. **Загрузка кадров** (заменяет fetch RainViewer):
   - `fetch('https://rainradar.ru/composite/manifest.json?t='+Date.now())`;
   - отфильтровать по `ts`, отсортировать по возрастанию;
   - `frames[] = { ts, tiles: z3/z4/z5 списки, future: false }`.

2. **Overlay-слой** (заменяет `RecolorLayer`):
   - это `L.GridLayer` с `createTile(coords, done)`, один экземпляр на кадр (как в rainradar.ru: `new L.RadarLayer(id, ts, sets)`);
   - для view-тайла `(x, y, z)` вычислить `dz`; parent-тайл данных `(floor(x*scale), floor(y*scale), dz)`; если его нет в `sets[dz-3]` — тайл прозрачный (без сетевого запроса);
   - иначе загрузить raw PNG 264×264 (кэш по URL), взять красный канал, пересемплировать в 256×256 view-тайл, повторив алгоритм worker'а rainradar (формула ниже);
   - **без** `maxNativeZoom` (генерируем настоящий тайл каждого view-зума), `maxZoom = 10`, `minZoom = 3` (как у rainradar), `opacity: 0.9`. Качество на высоких зумах соответствует самому rainradar.ru (данные dz5 апскейлятся — это свойство источника).

3. **Алгоритм пересемплировки** (повторяет `renderTileSingle.js`, вход — красный канал PNG 264×264, значение 0..~70):
   - для каждого пикселя `(m,h)` из 256×256: `N=(B+m)*scale-K`, `D=(Y+h)*scale-V`, где `B=256*vx`, `K=256*dataX`, `Y=256*vy`, `V=256*dataY`;
   - бикубическая интерполяция по 4×4 соседям raw-массива (индекс `o+3+(s+3)*264`, центрировано в 264-тайле); промежуточные `b,j,y,L` по строкам, итог `v`;
   - `v<=0` → прозрачный; иначе цвет по `i=Math.round(v/70*700)*4` из LUT 700 шейдов RGBA (clamp к последнему индексу).

4. **Цветовая схема** — **оригинальная палитра rainradar** (стопы 0/1/5/11/15/30/40/47/58/60, решение пользователя 2026-08-11): 1:1 с источником, включает облачность (1–4) и грозы/град (≥58 фиолетовый).

5. **Легенда**: обновляется под оригинальную палитру — градиент `[синий, зелёный, жёлтый, оранжевый, красный, фиолетовый]`, надписи по стопам палитры. Текущий макет (`#legend`) не меняется.

## Тестирование

- Единичные тесты (`tests/test_radar.py`): обновить asserts на новые URL (убрать `tilecache.rainviewer.com`, `api.rainviewer.com`, добавить `rainradar.ru/composite/manifest.json`, `/composite/{ts}/{dz}/`).
- Живой чек: headless-скриншот на точке «Тверь 57.55, 35.03 z8» — осадки присутствуют (rainpix ≥ 1 в области), сверка с rainradar.ru.
- Ручная проверка манифеста: для 2–3 произвольных тайлов зоны РФ наличие в manifest совпадает с наличием ненулевых пикселей.

## Ошибки и деградация

- Если manifest или тайл упал: `setStatus('Радар недоступен: …')` и повтор через 30 с (как сейчас для RainViewer);
- тайлы без покрытия из манифеста → прозрачные, без лишних запросов;
- `crossOrigin='anonymous'` для raw-тайлов (CORS `*` — ок).

## Вне скоупа

- Прогноз/nowcast (у RainViewer был; у rainradar отсутствует) — поле `future` станет всегда `false`, таймлайн без «(прогноз)».
- Слой молний от WetterOnline — недоступен (закрыт).
- Гроза/град от rainradar — приходят автоматически как фиолетовые значения ≥58, если выбрана оригинальная палитра.
