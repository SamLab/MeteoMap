# Дизайн: мультилокация (Ярославль, Балакирево, Цеденево)

Дата: 2026-08-06

## Цель

Добавить поддержку нескольких локаций: переключение города по клику на название в шапке. Первая версия — 3 города: Ярославль (57.63, 39.87), Балакирево (56.507, 38.846), Цеденево (57.533, 39.905). Все в часовом поясе Europe/Moscow.

Проверено на живых данных: прогноз Цеденево не дублирует Ярославль (макс. расхождение температуры 2.8°C за 16 дней, осадки 20.9 vs 18.8 мм).

## Решения (одобрены пользователем)

- **Хранение:** отдельные JSON на город (`data/<slug>.json`), `index.html` лёгкий со списком городов.
- **Переключение:** клик по названию города в шапке → выпадающий список.
- **Батчинг Open-Meteo:** координаты всех городов одним запросом на модель (проверено: forecast и archive возвращают массив по городам, координаты округляются к сетке — нормально).
- **Веса:** свои веса MAE на город (исторический батч-архив).
- **Запоминание:** выбранный город сохраняется в localStorage.

## Архитектура

### Backend (`meteo.py`)

1. Заменить константы `LAT`/`LON` на список:

```python
LOCATIONS = [
    {"name": "Ярославль", "slug": "yaroslavl", "lat": 57.63, "lon": 39.87},
    {"name": "Балакирево", "slug": "balakirevo", "lat": 56.507, "lon": 38.846},
    {"name": "Цеденево", "slug": "tsedenevo", "lat": 57.533, "lon": 39.905},
]
```

2. `fetch_model` принимает список координат: `lats="57.63,56.507,57.533"`, `lons=...`. Ответ — список по городам (или одиночный объект, оборачиваем в список). Функция возвращает `{city_index: {...}}` или список.

3. Обработка на город в цикле `main()`:
   - для каждой модели — один батч-запрос, результат разбирается по городам;
   - Yr — отдельный запрос на город (`fetch_yr(lat, lon)` уже параметризован);
   - верификация — батч-архив на город, свои веса на город;
   - консенсус, payload — на город.

4. Вывод:
   - `index.html` — шаблон без `__DATA__`, но с `__CITIES__` (JSON-список городов: name, slug, lat, lon).
   - `data/<slug>.json` — полный payload города (то, что сейчас в `__DATA__`).

5. `build_payload` — параметр `location` (dict с name/lat/lon) вместо хардкода «Ярославль».

6. Совместимость с тестами: существующие функции получают город/координаты параметром с дефолтом на Ярославль, чтобы старые тесты не ломались.

### Frontend (`template.html`)

1. `<script id="data">` остаётся, но `D` заполняется асинхронно:

```js
let D=null;
async function loadCity(slug){
  const r=await fetch('data/'+slug+'.json',{cache:'no-cache'});
  D=await r.json();
  renderAll();
}
```

2. Все вызовы `buildXxx()` в конце (строки ~680-690) обернуть в `renderAll()`.

3. Заголовок: кнопка-селектор с названием текущего города (из `__CITIES__` или из `D.location.name`), по клику — выпадающий список городов. Выбор → `localStorage.setItem('city', slug)` → `loadCity(slug)`.

4. `<title>`, `__CITY__`, время генерации — обновляются из `D.location` и `D.generated_at`.

5. При ошибке загрузки — сообщение и возврат к текущему городу.

### Деплой (`.github/workflows/deploy.yml`)

- Копировать `index.html` **и** `data/` в gh-pages:

```yaml
cp index.html /tmp/ghpages/
cp -r data /tmp/ghpages/
```

### Верификация локально (headless)

`fetch` не работает из `file://` (CORS). `tools/headless_probe.py` доработать: копировать index.html + data/ во временную папку, поднять `python -m http.server` на случайном порту, гонять Edge на `http://localhost:PORT/`, убивать сервер. Так fetch-путь переключения проверяется как на live.

## Обработка ошибок

- Backend: сбой одного города/модели — `[warn]`, генерация продолжается; полный отказ — `SystemExit`.
- Frontend: ошибка fetch — сообщение, город остаётся прежним.

## Тесты

- `tests/test_locations.py` (новый): разбиение батч-ответа по городам, сбой города, Yr-перина, список городов в index.html.
- `tests/test_render.py`: адаптация под `data/<slug>.json` и `__CITIES__`.
- Существующие 88 тестов не должны сломаться.
- Headless-проба: переключение города на локальном index.html.

## Критерии готовности

1. `pytest tests -m "not integration" -q` — все зелёные.
2. `python meteo.py` — пишет `index.html` + `data/{yaroslavl,balakirevo,tsedenevo}.json`.
3. Headless-проба: переключение города работает, имена городов в селекторе, данные подставляются.
4. Локальный index.html открывается без `__DATA__`-плейсхолдера (или с корректным фолбэком на загрузку).

## Вне области (YAGNI)

- Батчинг Yr/MET Norway (нет в API) — по одному запросу на город, ок.
- Динамическое добавление городов через UI — только в коде/конфиге.
- Выбор города через URL (#city=...) — не нужно в первой версии.
