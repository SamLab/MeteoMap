# Параллелизация сетевых запросов в meteo.py

Дата: 2026-08-07
Статус: approved

## Цель

Сократить время шага `Generate site` в GitHub Actions с ~6 минут до ~1.5-2 минут,
сохранив стабильность к сетевых ретраев и не меняя логику консенсуса.

## Текущее состояние

Шаг `Generate site` (6:16 из 6:33 всего деплоя) выполняет ~48 последовательных
HTTP-запросов в `meteo.py`:

1. Forecast-батчи 13 моделей Open-Meteo (цикл в `main()`).
2. Верификация 7d/30d: archive + по 13 исторических моделей на окно
   (цикл в `verify_models`), с кэшем `_hist_cache`/`_arch_cache` по городам.
3. Внешние провайдеры YR, OWM, WeatherAPI × 3 города.

Запросы идут подряд; таймауты и ретраи в `request_with_retry` остаются.

## Решение

Использовать `ThreadPoolExecutor` (stdlib, без новых зависимостей)
с `max_workers=5` для параллельной загрузки независимых сетевых данных.
Остальная логика (нормализация, консенсус, рендер, запись) без изменений.

### Места правок в meteo.py

1. **Forecast-загрузка** (`main()`, цикл по 13 моделям):
   запускать `fetch_model` через пул; порядок `raw_by_model` сохранить.

2. **Верификация** (`verify_models`, цикл по моделям на окно):
   запускать `fetch_hist` через пул; порядок `result` сохранить.
   Archive-запрос остаётся до циклов (единственный).

3. **Внешние провайдеры** (`main()`, YR + OWM + WeatherAPI × 3 города):
   запускать загрузку строк параллельно; сборка `hourly_by_model` в прежнем порядке.

### Требования к реализации

- `max_workers=5` — компромисс между скоростью и риском rate-limit (429).
- Ретраи и таймауты (`request_with_retry`) не трогаются.
- Кэши `_hist_cache`/`_arch_cache` не меняются (ключи прежние).
- Результат каждой модели — детерминированный порядок, как сейчас.
- Для корректной сборки пул принимает и `fetch_hist`/`fetch_arch`-моки из тестов.

## Тестирование

- `python -m pytest tests/ -m "not integration"` — существующие юнит-тесты.
- Локальный прогон `meteo.py` с замером времени.
- После пуша — деплой и сверка live (generated_at свежий, 3 города, 13 моделей).

## Ожидаемый эффект

`Generate site`: ~6 мин → ~1.5-2 мин. Общий деплой: ~6.5 мин → ~2-2.5 мин.
