# Дизайн: Telegram-бот для MeteoMap (PHP-вебхук)

Дата: 2026-08-05
Статус: утверждено

## Цель

Бот для Telegram, который по команде в любой группе (или личном чате) выводит сводку погоды MeteoMap: текущие условия, максимум/минимум температуры по часам, ближайший дождь/грозу/град. Бот работает на shared-хостинге Hostland.ru (доступ по FTP), без долгоиграющего процесса.

## Архитектура

```
Telegram ──HTTPS POST──▶ https://<сайт>/bot.php ──▶ file_get_contents() ──▶ https://samlab.github.io/MeteoMap/index.html
      ◀──HTTP response──┘                                                                   │
      ◀──────────────────────── sendMessage (прямой вызов Bot API) ───────────────────────────┘
```

- Бот — **PHP-вебхук**: Telegram сам присылает update на `bot.php`, когда кто-то пишет боту. Долгий процесс не нужен, cron не нужен, держать терминал не нужно.
- Данные берутся из уже задеплоенного `index.html` (обновляется GitHub Actions каждый час). Бот вырезает JSON из `__DATA__` и считает сводку на PHP.
- Ответ отправляется прямым вызовом `sendMessage` в Bot API (не через ответ на вебхук).

## Формат ответа

Три строки (перенос строки `\n`):

```
Сейчас: ⚡ Пт 7 — +24°, ощущается как +25°
Осадки: 0мм · Ветер: 3 м/с ЮЗ · Давление: 756 мм рт. ст. · Влажность: 62%
По часам — без дождя / макс. +24° в 15:00 / мин. +17° в 23:00
На 16 дней — дождь Чт 6 в 14:00 на 0.1мм с 17% по 4 моделям / гроза Пт 7 в 10:00 на 1.1мм с 11% по UKMO Global / град Пт 7 в 14:00 на 1.3мм с 46% по DWD ICON
```

- «Сейчас»: иконка+текст погодного кода, день недели, температура, «ощущается как».
- Вторая строка: осадки (мм), ветер (м/с + румб), давление (мм рт. ст.), влажность (%).
- «По часам»: ближайший дождь сегодня по консенсусу (или «без дождя»), макс/мин за сегодня с временами.
- «На 16 дней»: ближайший дождь (консенсус, число моделей), гроза и град (по источникам, имена моделей).
- Подчёркивание дат (как на сайте) в Telegram plain-text не поддерживается — обычный текст.

## Данные

- Источник: `https://samlab.github.io/MeteoMap/index.html` (содержит `<script>...const __DATA__ = {...}</script>` или `window.__DATA__` — точную форму уточнить при реализации, в template.html строка 401: `"__DATA__", json.dumps(payload, ensure_ascii=False)`).
- Парсинг: вырезать JSON между маркером `__DATA__` и концом присваивания.
- Поля payload: `D.time` (массив ISO-строк часов), `D.weighted` (консенсус: `temperature_2m`, `apparent_temperature`, `precipitation`, `precipitation_probability`, `pressure_msl`, `relative_humidity_2m`, `wind_speed_10m`, `wind_direction_10m`, `weather_code`), `D.models` (per-model hourly: `weather_code`), `D.model_codes`, `D.model_names`.
- `curIdx` = индекс текущего часа по Москве (`Europe/Moscow`), как на сайте: первый `t` в `D.time` с `t >= nowLocal`.

## Команды

- `/погода`, `/weather`, а также любой другой текст — отвечает сводкой.
- Работает в группах и личных чатах; отвечает любому участнику.
- `/start` — приветствие + подсказка.

## Формулы (перенос JS-логики с сайта на PHP)

1. **Макс/мин за сегодня**: по часам текущего дня (`D.time[start]`), `max`/`min` `temperature_2m`, с временем.
2. **Дождь сегодня (По часам)**: первый час сегодня, где `weather_code` в `[51,53,55,56,57,61,63,65,66,67,80,81,82]`; иначе «без дождя».
3. **Ближайший дождь (На 16 дней)**: по консенсусу `D.weighted.weather_code`, от `curIdx`, код в списке дождей; число моделей с таким кодом в этот час = `по N моделям` / `по 1 модели`.
4. **Ближайшая гроза**: первый час от `curIdx`, где хоть у одной модели `weather_code` в `[95,96,99]`; имена таких моделей через « и ».
5. **Ближайший град**: первый час от `curIdx`, где хоть у одной модели `weather_code` в `[96,99]`; имена моделей через « и ».
6. **Осадки/вероятность в час**: `D.weighted.precipitation[час]` (мм, 1 знак), `precipitation_probability[час]` (%).

## Числовые форматы (как на сайте)

- `fmt` — 1 знак после запятой (`Math.round(v*10)/10`).
- `num` — целое.
- `temp` — `+23°` (знак для положительных).
- Давление: `HPA_TO_MMHG = 0.750061683`, округлить до целого.

## Настройка (один раз)

1. У @BotFather создать бота → получить токен.
2. Залить `bot.php` по FTP на Hostland в корень сайта.
3. Выполнить один раз: `https://<сайт>/bot.php?setup=<токен>` — зарегистрировать вебхук (вызов `setWebhook`).
4. Проверить: `?setup` выводит статус регистрации вебхука.

## Безопасность

- Токен хранится в `bot.php` (или в отдельном `config.php`, загружаемом по FTP). Указание токена в URL используется только для одноразовой настройки вебхука.
- При получении update проверять, что `secret` не нужен — вебхук публичный, но отвечает только на команды погоды.

## Файлы

- `bot.php` — весь бот в одном файле: парсинг входных данных, получение index.html, расчёт сводки, отправка ответа, обработка `?setup`.
- `README-bot.md` (необязательно) — инструкция по установке: BotFather, FTP-заливка, вызов `?setup`.

## Тестирование

- Локально: PHP-CLI (если установлен) или встроенный сервер `php -S localhost:8000` — отправка тестового update через `curl`.
- Формулы сверить с сайтом: значения заголовков «По часам» и «На 16 дней» на сайте == ответ бота на те же данные.
- Ошибки: если index.html недоступен или JSON не распарсился — ответ «Данные недоступны, попробуйте позже».

## Вне объёма (YAGNI)

- Расписания (крон-рассылки) — только по запросу.
- Несколько городов — только Ярославль.
- Инлайн-клавиатуры — не нужны.
- Хранение пользователей — не нужно.
