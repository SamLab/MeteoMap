# Переключатель шапки виджета: ближайшие / подтверждённые осадки

Дата: 2026-10-08. Статус: реализовано.

## Проблема

В шапке виджета (meteo.html, meteow.html) сводка по дождю показывает «ближайшие
осадки»: интервал начинается с первого часа, где дождь отмечает консенсус ИЛИ
минимум две модели. Если начало эпизода не подтверждено консенсусом, строка
начинается со слов «Вероятны Осадки» — но увидеть, что именно подтверждают все
модели ("подтверждённые осадки"), невозможно.

## Решение

Клик по иконке погоды в шапке (span.cico) переключает сводку между двумя
строками, как в «Предупреждениях» главной страницы (wr1/wr2):

- **ближайшие** (`buildSummary`, режим по умолчанию) — текущее поведение, не
  изменяется. Интервал по объединённому критерию (консенсус ИЛИ >=2 модели),
  строка «Вероятны Осадки …» для неподтверждённого начала, счётчик — по строгому
  критерию (>33%).
- **подтверждённые** (`summaryConfirmed`, новая функция) — интервал только по
  консенсусу (дождевой код, или осадки >=0.1 мм, или осадки <0.1 мм с
  вероятностью >20%). Текст повторяет подтверждённую ветку `buildSummary`
  (тип + интервал + [сумма*макс.%] + счётчик по консенсусу). Консенсусного
  дождя нет — «Остаток дня без дождя» (в обоих режимах, как у «Предупреждений»).

### Механика

- Состояние — `var headMode='nearest'` в замыкании виджета; переживает
  автообновления (`.load()` каждые 5 минут и по `visibilitychange`).
- `render()` сохраняет контекст (`hTimes/hData/hWdg/hRaw/hIdx`) и зовёт
  `refreshHeader()`; собранная строка ровно та же, что и раньше
  (`headParts` + `join(', ')`), поэтому форма шапки не изменилась.
- `refreshHeader()` подставляет строку по режиму, вешает на `span.cico`
  `title` (подсказка с названием текущего и альтернативного режима) и клик
  (`toggleHead`). Иконка пересоздаётся при каждой перерисовке, поэтому
  слушатель вешается заново.
- Видимая кликабельность — `cursor:pointer` у `.city .cico`.

### Границы

- Виджеты остаются ES5 (`var`, без `?.`, `const`, стрелочных функций).
- `buildSummary` не изменена; дождевые коды у `summaryConfirmed` объявлены
  локально (как `SENSOR_RAIN_CODES`): `RAIN` принадлежит `buildSummary`, и
  ссылку на него снаружи проверка `test_widget_rain_codes_do_not_borrow_buildsummary_scope`
  считает ошибкой. Виджет исполняется целиком в node (stub DOM): `refreshHeader`
  застрахован от отсутствия `.cico` (тестовый stub возвращает null).
- Справка (template.html): упомянут переключатель.
- Различие режимов видно и по `title`: «Ближайшие осадки — клик:
  подтверждённые» и «Подтверждённые осадки — клик: ближайшие». Дважды
  «Остаток дня без дождя» — клик без видимого эффекта (обе строки одинаковы).

## Согласованные решения

- При отсутствии консенсусного дождя подтверждённый режим показывает
  «Остаток дня без дождя» (не разделяет «нет вовсе» и «нет по консенсусу»).
- Аффорданс — только `cursor:pointer` + `title`, без подсветки активного режима.

## Тесты

`tests/test_radar.py`:

- `test_widget_header_toggle_between_nearest_and_confirmed` — наличие
  `summaryConfirmed`, консенсус-интервала и переключателя в обоих виджетах;
  `cursor:pointer`, оба `title` (кириллица второго виджета расшифровывается
  из \u-escape); ES5; фраза справки в template.html.
- `test_widget_summary_prefers_nearest_rain_not_later_confirmed` — тело
  `buildSummary` по-прежнему использует объединённый критерий (чисто
  консенсусный скан проверяется только в `summaryConfirmed`).
- `test_widget_header_*` (существующие needles) — строка сборки шапки уникальна,
  форма `headParts`/`innerHTML` не изменилась; `widgetSensorTemp` зовётся с полными
  данными (`hData`), сводка — с `hWdg` (`data.weighted`).

`tests/test_render.py::test_widget_renders_without_swallowing_errors` —
виджет исполняется целиком в node и уходит в отрисовку с температурой датчика
в шапке (ловит ошибки типа «RAIN is not defined» и null-узлов).
