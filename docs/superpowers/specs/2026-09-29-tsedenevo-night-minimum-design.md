# Ночной минимум датчиков для Цеденево — дизайн

Дата: 2026-09-29
Статус: утверждён

## Задача

На главной странице в строке «По датчику» Ярославль показывает среднее
температур по всем доступным станциям. Для Цеденево днём — то же среднее,
а в ночные часы — минимум по тем же станциям. Минимум отвечает на вопрос
«насколько холодно в самом холодном месте», который ночью и есть практический
вопрос: риск заморозка в низине, а не городское среднее.

Изменение касается только строки «По датчику». Столбик «Датчик» в таблице
«Часы» остаётся средним в любое время суток.

## Факт, определяющий конструкцию

У Цеденево нет своих станций. В `tools/stations.json` четыре станции, и все
они в Ярославле (57.55–57.63 / 39.76–39.92); Цеденево — 57.533 / 39.905.
Данные в столбике «Датчик» на странице Цеденево побайтово совпадают с
ярославскими: `sensor_station_counts` идентичны, `models.sensors` идентичны.

Решено: «датчики Цеденево» — это те же четыре ярославские станции. Собственные
станции в Цеденеве не ищутся. Разброс между ними велик и делает замысел
рабочим: за час 21:00 Пенаты 6.62, Фрунзе 11.08, Восток 11.25, Берег 12.70 —
среднее 10.4 против минимума 6.6, почти четыре градуса.

## Решения

| Вопрос | Решение |
|---|---|
| Набор станций для Цеденево | те же четыре, что и у Ярославля |
| К какому моменту привязано «день/ночь» | к часу показания, а не к моменту просмотра |
| Способ доставки минимума | новый верхнеуровневый ключ payload |
| Столбик «Датчик» в таблице «Часы» | без изменений, всегда среднее |
| Дефолт при нехватке данных | среднее |

## Серверная часть

### Подсчёт

`_sensor_hour_value` (`meteo.py:1109-1138`) возвращает сегодня
`(mean, count)`. Меняется на `(mean, minimum, count)`:

```
mean    = round(sum(per_station) / len(per_station), 2)   # как сейчас, :1138
minimum = round(min(per_station), 2)
```

Оба значения считаются из **одного и того же** списка `per_station`.
Инвариант: среднее и минимум всегда описывают один и тот же набор станций.
Если считать их раздельно по разным фильтрам, переключение день/ночь может
сравнить среднее по четырём станциям с минимумом по двум, и строка станет
бессмысленной. Перебор `per_station` (`:1127-1135`) не меняется.

Среднее по-прежнему взвешено по станциям равно, а не по числу замеров:
`apply_sensor_weights` и существующая семантика не трогаются.

### Модель и payload

`load_sensor_model` (`:1141-1186`) добавляет в возвращаемый словарь
`station_min` — массив длиной с сетку, параллельно `station_counts`
(`:1183`). Там, где данных нет, `None`, как у `data[var]`.

`build_payload` (`:1503-1518`) публикует его верхнеуровневым ключом
`sensor_station_min` рядом с существующим `sensor_station_counts`, и только
когда модель есть. У семи городов без станций ключ не появляется — так же,
как сейчас не появляется `sensor_station_counts`.

Ключ отправляется в оба города; Ярославль его проигнорирует. Собирать его
только для Цеденево означало бы завести ради 2 КБ спецслучай по slug.

Прирост payload — один массив из 384 чисел на город, около 2 КБ.

Форма ключа повторяет форму `sensor_station_counts`:

```json
"sensor_station_min": {"temperature_2m": [6.62, null, 6.5, ...]}
```

Ключ держится на верхнем уровне, а не внутри `models["sensors"]`, по уже
записанной в `meteo.py:1511-1514` причине: `models[code]` читается как
параллельные ряды по переменным, и не-массивный элемент сломал бы сборку
графика.

## Клиентская часть

### Определение города

`D.location.slug` уже присутствует в payload — проверено: Ярославль
`yaroslavl`, Цеденево `tsedenevo`. Отдельного запроса не требуется.

### Ночь или день

Новый помощник `sensorIsDay(hourIso)`:

1. день часа: `hourIso.slice(0,10)`, его индекс `k` в `D.daily_time`
2. `sunrise = D.daily.sunrise[k].slice(11,16)`, `sunset = D.daily.sunset[k].slice(11,16)`
3. день, если `sunrise <= hourIso.slice(11,16) < sunset`, иначе ночь

Строковое сравнение корректно: обе стороны — «ЧЧ:ММ» с ведущими нулями,
одно локальное моское время (`TIMEZONE = "Europe/Moscow"`).

Границы на примере рассвета 06:20, заката 18:01:

| час | исход | почему |
|---|---|---|
| 05:00 | ночь | час до рассвета |
| 06:00 | ночь | час начинается раньше 06:20 |
| 07:00 | день | после рассвета |
| 18:00 | день | час ещё не перевалил 18:01 |
| 19:00 | ночь | после заката |

Если `k` не найден или `sunrise`/`sunset` отсутствуют, дефолт — **среднее**.
Обратный дефолт переключил бы поведение по отсутствующим данным, а
нехватка данных не должна менять то, что показывается.

### Выбор значения

`lastSensorHour()` (`template.html:394-416`) дополнительно отдаёт `min` —
значение из `D.sensor_station_min` для того же часа, либо `null`. Поиск часа
и проверки `n[j] > 0 && x != null` остаются прежними: они отвечают за то,
что бакет вообще наблюдался, и не за то, среднее это или минимум.

Выбор в строке рендера (`template.html:488`):

- `slug === 'yaroslavl'` → всегда `value`
- `slug === 'tsedenevo'` → `sensorIsDay(sn.hour)` ? `value` : `min`
- нужного значения нет → откат на `value`
- нет и его → строка скрывается целиком, как сейчас

Знак, формат `fmt()` и подпись часа в скобках не меняются.

## Тесты

Сервер, в `tests/test_locations.py`:

- `_sensor_hour_value` возвращает минимум по пер-станционным средним, а не
  по сырым замерам (станция с двумя замерами не должна перевешивать станцию
  с одним)
- среднее и минимум приходят из одного набора станций
- `station_min` выровнен по сетке, `None` там, где данных нет
- `build_payload` публикует `sensor_station_min` верхнеуровневым ключом с
  той же формой, что `sensor_station_counts`
- у города без станций ключа нет

Клиент, в `tests/test_render.py`:

- Цеденево днём берёт среднее, ночью — минимум
- Ярославль всегда берёт среднее, в том числе ночью
- границы: час до рассвета — ночь, час, вмещающий рассвет, — ночь
- при отсутствии `sensor_station_min` строка не ломается и остаётся средней
- `lastSensorHour` прячет бакет без наблюдения независимо от выбора

Существующие шесть тестов строки «По датчику» (`:395-466`) продолжают
проходить: поведение Ярославля не меняется.

Полный набор `pytest tests/ -m "not integration"` — зелёный.

## Что не входит

- поиск и подключение реальных станций в Цеденеве
- график или отдельный столбик «минимум» в таблице «Часы»
- civil twilight, сумерки, золотой час — в payload только `sunrise`/`sunset`
  дневного уровня, per-hour солнечного флага не существует
- показ минимальной станции поимённо
