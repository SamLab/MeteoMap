# Спецификация: Слой спутниковой облачности (NASA GIBS) на вкладке «Спутник»

Дата: 2026-09-04
Статус: дизайн (на ревью)
Проект: MeteoMap (`F:\Meteo`)

## 1. Проблема и цель

На вкладке «Спутник» (`nowcast.html`) сейчас отображается наукастинг осадков ГМЦ (слой `NowcastLayer`, читает R-канал PNG-тайлов) и молнии (Blitzortung). **Изображений облачности на странице нет**: в сухую погоду тайлы наукастинга полностью прозрачны, и пользователь видит только пустую базовую карту. Радар на соседней вкладке тоже не показывает облака отдельно.

Цель: добавить на вкладку «Спутник» **отдельный переключаемый слой спутниковой облачности**, чтобы облака были видны всегда (и в сухую погоду), как на реальных метеокартах.

## 2. Выбор источника (исследование завершено, подтверждено эмпирически)

Перебраны все основные бесплатные кандидаты без ключа:

| Источник | Спутник | Ключ | CORS | Статус проверки |
|---|---|---|---|---|
| **NASA GIBS (MODIS TrueColor)** | да | нет | `Access-Control-Allow-Origin: *` | **работает** (JPEG 200 на z=9) |
| RainViewer satellite | да | нет | — | пуст (`satellite.infrared: []`) |
| EUMETSAT Meteosat | да | да/доступ | — | недоступен с этой сети (таймаут) |
| Meteoblue satellite | да | да (403) | — | нужен рабочий ключ + макс. zoom 6 |
| Windy | да | токен | — | 404 |
| Sat24 | да | нет | — | 403/404 |
| met.no / Yr.no WMS | — | нет | — | 503 |
| OpenWeatherMap clouds | модель, не спутник | да | — | не подходит |

**Решение: NASA GIBS**, продукт `MODIS_Terra_CorrectedReflectance_TrueColor` (+ опционально `MODIS_Aqua_...`). Единственный рабочий источник: бесплатный, без ключа, открытый CORS, реальные спутниковые снимки.

Ограничения источника (приняты):
- **Тайлы доступны только на zoom 9** (разрешение 250м; `TileMatrixSet=GoogleMapsCompatible_Level9`). На z<9 сервер отвечает 400 → нужен клиентский даунсемплинг.
- **Дневной снимок** (TrueColor = RGB): облака видны белыми днём; ночью снимок тёмный, облачность не отображается. Это принятое ограничение.
- **Обновление ~1–3 раза в сутки** (проходы MODIS Terra/Aqua ~10:30 и ~13:30 местного), с задержкой ~1–3 ч после пролёта.

## 3. Архитектура

### 3.1 URL тайла GIBS (проверен)

```
https://gibs.earthdata.nasa.gov/wmts/epsg3857/best/{PRODUCT}/default/{YYYY-MM-DD}/GoogleMapsCompatible_Level9/9/{y}/{x}.jpg
```

- `PRODUCT = MODIS_Terra_CorrectedReflectance_TrueColor`
- `{YYYY-MM-DD}` — UTC-дата снимка.
- `{x}`, `{y}`, `{z=9}` — координаты тайла (z всегда 9).
- Ответ: JPEG, `Access-Control-Allow-Origin: *`.

### 3.2 Утилита в `tools/nowcast.py`

Добавить в существующий `tools/nowcast.py` (уже есть для ГМЦ-наукастинга):
- `GIBS_BASE` — константа базового URL.
- `GIBS_PRODUCT = "MODIS_Terra_CorrectedReflectance_TrueColor"` (+ `GIBS_PRODUCTS` для Terra/Aqua).
- `gibs_tile_url(x, y, date)` → полный URL тайла (z всегда 9).

Юнит-тесты покрывают построение URL (паттерн регрессионного замка, как для `tile_url` наукастинга).

### 3.3 Клиентский рендер в `nowcast_template.html`

Существующая страница уже имеет: карту `L.map`, базовый слой `rainradar.ru/tiles`, `LabelsLayer`, молнии (`ltoggle`), `NowcastLayer` (наукастинг), таймлайн/play.

Добавляется:
1. **Кнопка-тумблер `#ctoggle`** «Облачность» — по образцу `#ltoggle` («Молнии»): белая/оранжевая, включает/выключает слой. В левом/правом верхнем углу рядом с молниями.
2. **Слой `L.tileLayer` для GIBS** — стандартный Leaflet-слой, подставляющий тайлы. Ключевое: GIBS отдаёт данные только на z=9, поэтому используется **`maxNativeZoom:9`** и **`minNativeZoom:9`**: при любом текущем zoom карты Leaflet сам подзагружает корректный набор z9-тайлов и отмасштабирует их под viewport (стандартный underzoom/overzoom, как для тайл-серверов с ограниченным зумом). Это исключает ручной canvas-даунсемплинг.
   - `options: {minZoom:3, maxZoom:10, minNativeZoom:9, maxNativeZoom:9, zIndex:900, opacity:~0.9, attribution:'Спутник: <a href="https://earthdata.nasa.gov/">NASA GIBS</a>'}`.
   - URL-шаблон (z в URL фиксирован как 9):
     ```
     L.tileLayer(gibsBase + '{x}/{y}.jpg', { ..., maxNativeZoom:9 })
     ```
     где `gibsBase` содержит product, дату и `.../GoogleMapsCompatible_Level9/9/`.
3. **Порядок слоёв**: облачность — под наукастингом (осадки поверх облаков), поверх базовой карты. Leaflet `zIndex`/порядок добавления: базовый `rainradar.ru` (zIndex 998) → `gibsLayer` (zIndex 900) → `LabelsLayer` → молнии → `NowcastLayer`. Т.е. облачность добавляется ниже `NowcastLayer`.

### 3.4 Интеграция в UI

- В разметку рядом с `#ltoggle` добавить:
  ```html
  <button id="ctoggle" title="Спутниковая облачность (NASA GIBS, дневной снимок)"><span class="ltdot"></span>Облачность</button>
  ```
  Стили — по образцу `#ltoggle`. Иконка-точка использовать существующую `.ltdot`.
- JS: `var cloudOn=true;` кнопка добавляет/удаляет `gibsLayer` из карты и переключает класс `.on`.
- Переключатель по умолчанию **включён** (чтобы облака были видны сразу — цель пользователя).
- **Атрибуция**: строка в правом нижнем углу Leaflet (`attribution`), источник NASA GIBS.

### 3.5 Автообновление даты снимка

Т.к. снимок обновляется раз в сутки, дата определяется один раз при инициализации:
- `var cloudDate = new Date().toISOString().slice(0,10);` → передаётся в `gibs_tile_url`.
- При перезагрузке страницы / обновлении `load()` (каждые 5 мин) дата не пересчитывается часто — достаточно пересчитывать раз в ~30–60 мин, чтобы подхватить новый дневной снимок. (Опционально: раз в 30 мин переустанавливать `cloudDate` и `redraw()`.)

## 4. Обработка ошибок

- При недоступности тайла/сети — тайл остаётся прозрачным, слой просто не показывает облака (не падает). Логика поведения как у `renderTile` наукастинга: `catch → прозрачный тайл`.
- GIBС 400 на z!=9 не возникнет, т.к. мы всегда запрашиваем z=9.
- Ретрай не требуется агрессивно (снимок статичен за сутки); при сбое следующая загрузка при `redraw`/повторе подхватит. (Можно переиспользовать ретрай-логику `loadRaw` если потребуется — решение в плане.)

## 5. Область вне scope

- НЕ менять `radar.html`, `radar_template.html`, вкладку «Радар», `NowcastLayer` (наукастинг), молнии.
- НЕ добавлять ночную облачность (нет источника без ключа).
- НЕ добавлять покадровую анимацию облаков (полюсный спутник — снимок, не геостационар; движение облаков недоступно бесплатно).

## 8. Открытые вопросы (решаются в плане)

- **Дата снимка**: точная стратегия определения/обновления `cloudDate` (при инициализации и периодически) и число отступа дней, чтобы гарантированно получить свежий дневной снимок (debounce/fallback на предыдущий день при 400/прозрачном снимке).
- **Поведение на z>9**: с `maxNativeZoom:9` Leaflet автоматически растянет z9-тайлы на z=10 (нерезко) либо можно задать `maxZoom:9` для слоя — выбрать в плане.
