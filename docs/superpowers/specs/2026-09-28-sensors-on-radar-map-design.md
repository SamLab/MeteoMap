# Дизайн: метеодатчики сети на вкладке «Радар»

Дата: 2026-09-28
Статус: принято

## Контекст / Задача

Показать показания собственных метеодатчиков сети на вкладке «Радар» (`radar.html`) как маркеры с привязкой к локациям.

## Проверенные факты об источнике

Брокер `yar.gorod76.ru:1883` — MQTT без аутентификации, подписка `#` отдаёт 151–181 топик (зависит от прогона). Доступен стабильно.

### Почему не «живая» подписка из браузера

| Порт | Состояние |
|---|---|
| 1883 (plain MQTT/TCP) | открыт |
| 8083, 9001, 8084 (WebSocket) | закрыты / таймаут |
| 80, 443 | открыты, но `yar.gorod76.ru` отдаёт 404 |

Браузер умеет MQTT только по WebSocket, и только защищённому (`wss://`), т.к. сайт на GitHub Pages по HTTPS. Настоящее live-обновление потребовало бы включать WebSocket + TLS на брокере. **Решение: снапшот раз в 15 минут.** Датчики публикуют раз в 10–55 с, окно сбора 4 минуты ловит их с гарантией.

### Почему нельзя брать retained как «данные»

Retained хранит последнее значение, но **не время публикации**. Отдельный LWT `state=offline` бывает stale — например у `/yarbatut/`, который при этом шлёт живые температуры.

В данных много заглушек:

| Канал | Значение | Комментарий |
|---|---|---|
| `city/out/zavolga/penaty/humavg` | `99.99` | заглушка влажности |
| `city/out/frunze/hum/left` | `99.99` | заглушка |
| `city/out/frunze/yarecologia/press` | `748.93` | заглушка давления |
| `.../yarecologia/diesel`, `/petrol`, `/kerosene`, `/turpentine`, `/white_spirit` | `748.9` | тот же сломанный канал |
| `city/out/frunze/yarecologia/all` | `"date":"23.05.25, 08:48"` | протухло более чем на год |

**Решение: снапшот не читает retained как данные.** Скрипт подписывается и слушает живой эфир; в JSON попадает только реально пришедшее, с меткой «сколько секунд назад» и флагом `retain`. Не услышанное за окно = `offline`.

## Форматы payload

Два разных формата в одной сети:

- JSON-обёртка — `/bereg/…`, `/dbereg_2/…`, `/yarbatut/…`:
  `{"status":"20.4"}` (иногда `{"status":"offline"}` для LWT)
- голое число — `city/out/…`, `city/in/…`: `13.62`
- `city/out/frunze/yarecologia/all` — вложенный JSON, разбирается или отбрасывается

Парсер обязан снимать `status` из объекта и парсить float из голой строки; строка `on`/`off`/`offline` — не число, уходит в отброс.

## Архитектура

```
tools/stations.json          конфиг: id, название, lat/lon, ключи -> топики
        │
        ▼
tools/collect_sensors.py     подписка + окно сбора + валидация
        │
        ▼
sensors.json                 снимок в корне репозитория
        │
        ▼  git commit + push
.github/workflows/deploy.yml (уже существует, cron '0 * * * *') → GitHub Pages
        │
        ▼
radar_template.html          fetch('sensors.json') → circleMarker
        │
        ▼
tools/build_radar.py         сборка radar.html из шаблона
```

### Почему `sensors.json` в корне, а не в `data/`

`data/` перечислена в `.gitignore` («Generated per-city data»), туда нельзя класть файл, который должен попасть на Pages. Корень репозитория не игнорируется.

### Отдельный workflow

`.github/workflows/sensors.yml`, cron `*/15 * * * *`. Коммит снапшота сам разбудит `deploy.yml` (у него `push: branches: [main]`), поэтому публикация не ждёт своего часового расписания.

## Валидация значений

| Величина | Диапазон | Особое правило |
|---|---|---|
| температура | −50 … +50 °C | — |
| влажность | 0 … 100 % | ≥ 99.5 → заглушка, отброс |
| давление | 600 … 820 мм рт. ст. | — |
| освещённость | 0 … 200000 лк | — |
| скорость ветра | 0 … 60 м/с | — |
| любая | — | `NaN` → отброс |

Значение `748.9` **не** отсекается диапазоном: это правдоподобное давление (~750 мм рт. ст.). Оно повторяется в `diesel`, `petrol`, `kerosene`, `turpentine`, `white_spirit` — то есть это один сломанный канал. Такие топики исключаются тем, что их **не вносят в конфиг**: `city/out/frunze/press` = 765.51 (рабочий) и `city/out/frunze/yarecologia/press` = 748.93 (сломанный) — разные топики, и в конфиг попадает только первый.

Заглушка `99.9…` в влажности, наоборот, надёжно ловится порогом: `city/gps/*/speed` держит ~99.97, и такой топик, ошибочно отображённый на влажность, будет отброшен.

Отброшенные значения пишутся в поле `rejected` с указанием причины, чтобы был виден сломанный канал, а не молча потерянный.

Станция считается `online: true`, только если в окне сбора пришло хотя бы одно валидное значение.

## Формат `sensors.json`

```json
{
  "generated_at": "2026-09-28T12:00:00Z",
  "window_s": 240,
  "stations": [
    {
      "id": "yarbatut",
      "name": "Ярбатут",
      "lat": 57.64033,
      "lon": 39.88513,
      "online": true,
      "age_s": 12,
      "values": {"t1": 20.4, "t2": 20.9, "t3": 28.9},
      "rejected": []
    }
  ]
}
```

`age_s` — секунд с момента последнего живого сообщения до конца окна сбора. Для `offline` — `null`.

## Станции и координаты

Координат в брокере **нет**: `esphome/discover` содержит только приватные IP (`192.168.1.120`, `192.168.1.201`), `city/gps/*` — это дорожный трафик (`jammed`, `speed`, `satellites`), а не позиции станций. Координаты задаются в конфиге вручную. Часть подтверждена геокодером по OpenStreetMap, часть — приблизительная (погрешность 1–2 км, для маркера незаметна; принято пользователем).

| id | Название | lat | lon | Точность | Топики |
|---|---|---|---|---|---|
| `yarbatut` | Ярбатут | 57.64033 | 39.88513 | точная | `/yarbatut/2054001-1458270/dstmp{4_0,4_1,5_0}/status` |
| `penaty` | Пенаты | 57.63040 | 39.91527 | точная | `city/out/zavolga/penaty/{tempavg,humavg,illuminance,dewpoint}` |
| `zavolzhye` | Заволжье | 57.64884 | 39.95075 | примерная | `city/internet/yaroslavl/mts/zavolga` (маркер-ориентир) |
| `frunze` | Фрунзе | 57.58337 | 39.90823 | примерная | `city/out/frunze/{temp/left,temp/right,hum_avg,press,pm2_5,pm10}` |
| `east` | Восток | 57.62000 | 39.92000 | примерная | `city/out/east/{temp/ds,temp/bme,hum,press}` |
| `west` | Запад | 57.64000 | 39.85000 | примерная | `city/{in,out}/west/temp/ds` |
| `bereg` | Берег | 57.55000 | 39.76000 | примерная | `/bereg/2708554-1458260/{tmp315,Hum339}/status`, `/dbereg_2/5438543-1458270/tmpwifi1/status` |

Заволжье — единственная станция-ориентир без метеоданных; при отсутствии значений она не рисуется, но задаёт географию.

Не включаются: `tasmota/…/Temperature` (температура чипа ESP32, не метео), `city/in/co2Lights/1` и `city/hum/1/relay` (реле), `city/internet/*` и `city/gps/*` (не датчики), `zigbee2mqtt/*` и `city/ha/*` (мосты).

## Отображение в `radar_template.html`

Правки вносятся **в шаблон**, `radar.html` генерируется через `tools/build_radar.py` (правки в нём не нужны).

- своя pane `sensors` с `zIndex` выше 998 (тайлы осадков) и 900 (подписи), иначе маркеры скрыты — та же причина, по которой пришлось вводить `overlayPane` в nowcast;
- `L.circleMarker` радиусом по zoom: на `z<6` — 5 px, `z 6–8` — 7 px, `z>8` — 9 px; тёмно-зелёная обводка, заливка `#36b343` при `online`, `#9a9a9a` при `offline`;
- подпись с числом температуры рядом с маркером, тем же стилем `text-shadow`, что у существующих `.label span`;
- кнопка `#stoggle` «Датчики» рядом с `#ltoggle` «Молнии», состояние `on`/`off` как у молний;
- `fetch('sensors.json?t=' + Date.now())` при загрузке и `setInterval` на 15 минут — cache-busting, чтобы GitHub Pages не отдал старый файл;
- попап: название, все валидные значения с подписями, «обновлено N мин назад» либо «нет данных»;
- поведение при недоступном `sensors.json` — тихое отключение кнопки, карта продолжает работать;
- таймлайн анимации радара не трогаем: маркеры показывают текущее состояние независимо от кадра.

## Тестирование

- `tests/test_sensors.py`: разбор обоих payload-форматов; отброс `99.99` и `748.9`; границы диапазонов; станция без живых сообщений → `online: false`; валидация `tools/stations.json` (уникальность id, диапазон lat/lon, непустые топики);
- сухой прогон `tools/collect_sensors.py` против реального брокера;
- `tools/headless_probe.py` по собранному `radar.html` — маркеры появились, `fetch` отработал, ошибок в консоли нет.

## Решения и их цена

| Решение | Почему | Цена |
|---|---|---|
| Снапшот 15 мин вместо live | WebSocket-портов на брокере нет, нужен TLS | данные отстают до 15 минут |
| Координаты вручную | в брокере координат нет | 4 станции с погрешностью до 2 км |
| `sensors.json` коммитится | `data/` в `.gitignore` | коммит каждые 15 минут в историю |
| Окно сбора 4 минуты | датчики шлют раз в 10–55 с | Job держит раннер ~4 минуты |
