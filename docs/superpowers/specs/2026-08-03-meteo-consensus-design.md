# Дизайн: MeteoMap — сравнение погодных моделей для Ярославля

Дата: 2026-08-03
Статус: утверждён

## 1. Цель

Статический сайт, который для одной точки — Ярославль (57.63°N, 39.87°E) — показывает
почасовой прогноз на 7 дней от ~12 глобальных погодных моделей (полученных через один
бесплатный API Open-Meteo) и выводит **усреднённый (консенсусный) прогноз** двумя
способами: взвешенным по исторической точности моделей и простым средним/медианой.

Обновление данных — раз в час. Своей базы данных и истории нет.

## 2. Термины

- **Модель** — конкретная численная погодная модель (GFS, ICON, ECMWF IFS и т.д.),
  запрашиваемая у Open-Meteo через параметр `models=`.
- **Консенсус** — усреднённый прогноз, построенный из всех доступных моделей.
- **Взвешенный консенсус** — среднее по весам, где веса обратно пропорциональны
  средней абсолютной ошибке (MAE) модели за прошлые 7/30 дней.
- **Простой консенсус** — среднее арифметическое и медиана по моделям на каждый час.
- **Historical Forecast API** — API Open-Meteo, отдающий архив прошлых прогнозных
  запусков моделей (нужен для верификации без собственной истории).

## 3. Источники данных

Единственный провайдер — **Open-Meteo** (free, non-commercial, без API-ключа, CORS,
до 10 000 запросов/день). Лицензия данных — CC BY 4.0 (на сайте указывается
«Weather data by Open-Meteo.com»).

### 3.1 Модели (глобальные — только они покрывают Ярославль)

| Код Open-Meteo | Модель | Происхождение |
|---|---|---|
| `ecmwf_ifs025` | IFS 0.25° | ECMWF |
| `ncep_gfs025` | GFS Seamless | NOAA, США |
| `dwd_icon_global` | ICON | DWD, Германия |
| `gem_global` | GEM Global | Environment Canada |
| `ukmo_global_deterministic_10km` | UKMO Global | UK Met Office |
| `meteofrance_arpege_world025` | ARPEGE | Météo-France |
| `jma_gsm` | GSM | JMA, Япония |
| `kma_gdps` | GDPS | KMA, Корея |
| `bom_access_global` | ACCESS-G | BOM, Австралия |
| `cma_grapes_global` | GRAPES | CMA, Китай |
| `ecmwf_aifs025` | AIFS (ML) | ECMWF |
| `google_weathernext` | WeatherNext (ML) | Google |
| `ncep_gefs025` | GEFS (ансамбль, mean) | NOAA |

Точный список кодов моделей фиксируется константой `MODELS` в `meteo.py` и
проверяется при реализации интеграционным тестом. Если какая-то модель не
покрывает Ярославль или не отвечает — она пропускается с пометкой «нет данных».
Примечание: ансамблевые и ML-модели (GEFS, AIFS, WeatherNext) могут отдаваться
Open-Meteo с отдельного ensemble-эндпоинта (`/v1/ensemble`) — сборщик учитывает
это и для них использует соответствующий эндпоинт.

### 3.2 Переменные (часовые, 7 дней)

`temperature_2m, apparent_temperature, dew_point_2m, relative_humidity_2m,
precipitation, precipitation_probability, snowfall, weather_code, pressure_msl,
cloud_cover, wind_speed_10m, wind_direction_10m, wind_gusts_10m, visibility,
shortwave_radiation`

Суточные агрегаты: `temperature_2m_max, temperature_2m_min, precipitation_sum,
wind_speed_10m_max, sunshine_duration`.

Параметры запроса: `latitude=57.63, longitude=39.87, timezone=Europe/Moscow,
forecast_days=7, hourly=..., daily=...` + `models=<одна модель за раз>`.

Суточные агрегаты используются в карточке текущих условий (температура max/min
на сегодня, сумма осадков) и на вкладке сравнения.

## 4. Архитектура

### 4.1 Пайплайн (однопроцессный скрипт `meteo.py`)

```
сборщик (models → таблица час×переменная)
  → верификатор (Historical Forecast API → MAE за 7/30 дней)
  → консенсус-движок (весовой + простой)
  → генератор index.html (статическая страница с встроенным JSON)
```

### 4.2 Деплой — паттерн MopedMap

- `deploy.yml` (GitHub Actions):
  - триггеры: `workflow_dispatch` (основной, вызывается cron-job.org раз в час),
    `schedule: cron '0 * * * *'` (резервный), `push` в `main`
  - шаги: `actions/checkout@v5` → `actions/setup-python@v5` (3.13) →
    `pip install -r requirements.txt` → `python meteo.py` (генерирует `index.html`) →
    force-push в ветку `gh-pages` через `GITHUB_TOKEN`
  - `permissions: contents: write`
- GitHub Pages настроены на ветку `gh-pages`, корень `/`.
- **Внешний планировщик cron-job.org** раз в час вызывает
  `POST /repos/{owner}/{repo}/actions/workflows/deploy.yml/dispatches` с PAT
  (права Actions: write) — надёжнее встроенного крона GitHub.
- Копируются только `index.html` + `.nojekyll`.

## 5. Нормализация данных

- Каждая модель → таблица `час × переменная`.
- Пропуски (модель не покрывает час/переменную) → `NaN`, исключаются из усреднения
  на этот час.
- Минимальное число источников для консенсуса по переменной на час — 3;
  иначе значение консенсуса = `null` (в UI «нет данных»).
- Единицы — стандартные Open-Meteo (°C, %, мм, м/с, hPa, Вт/м²), время — local
  Europe/Moscow.

## 6. Верификация и веса

- Источник: Historical Forecast API Open-Meteo для той же точки.
- Окна: 7 и 30 дней.
- Метрика: MAE по каждой модели для ключевых переменных:
  `temperature_2m`, `precipitation`, `wind_speed_10m`.
- Результат: `mae[модель][переменная]` за каждое окно.
- Если у модели нет архивных данных — она получает средний вес остальных моделей
  (не выпадает из консенсуса).

## 7. Консенсус-движок

На каждый час:

1. **Взвешенный**: `w_i = (1/MAE_i) / Σ_j(1/MAE_j)` для каждой переменной,
   консенсус = Σ w_i · x_i.
2. **Простой**: среднее арифметическое и медиана по моделям.

Особые переменные:
- `weather_code` (WMO, дискретная): голосование большинства; при равенстве —
  приоритет по неблагоприятности (дождь > облачно > ясно).
- `wind_direction_10m`: круговое (векторное) среднее.
- `precipitation_probability`: только модели, поддерживающие её; при < 3 источников
  → `null`.

Выходной JSON (встраивается в HTML):
`{generated_at, location, models:[...], verification:{7d:{},30d:{}},
hours:[{time, weighted:{var:val}, mean:{var:val}, models:{model:{var:val}}}]}`.

## 8. UI — `index.html`

Один статический файл. Chart.js с CDN, тёмная тема, русский язык. Данные — встроенный
JSON в `<script>`; интерактив — чистый клиентский JS. Внизу обязательная ссылка
«Weather data by Open-Meteo.com» (CC BY 4.0).

Три вкладки:

1. **Прогноз**
   - Шапка: «Ярославль», время генерации, обновлено раз в час.
   - Карточка текущих условий по взвешенному консенсусу (температура, ощущается,
     ветер, осадки, давление).
   - График температуры 7 дней: тонкие приглушённые линии моделей + жирная линия
     взвешенного консенсуса + пунктир среднего; чекбоксы включения моделей.
   - Графики осадков (бары консенсуса + линия вероятности) и ветра (линии).
   - Переключатель переменной: температура/ветер/осадки/влажность/давление/облачность.

2. **Сравнение моделей**
   - Таблица «час × модель + оба консенсуса», переключатель переменной,
     раскраска отклонения от консенсуса, горизонтальная прокрутка.

3. **Точность моделей**
   - Таблицы MAE за 7 и 30 дней по температуре/осадкам/ветру.
   - Бар-чарт рейтинга моделей.

Точный вид UI уточняется на этапе реализации («рисуем по факту») — общая структура
вкладок и графиков зафиксирована здесь.

## 9. Обработка ошибок

- Каждая модель загружается независимо, таймаут 15 с; сбой одной модели не роняет
  пайплайн — она помечается «нет данных».
- Полный сбой (все модели/сам Open-Meteo) → ненулевой код выхода → workflow падает →
  Pages остаётся со старой версией (безопасное поведение).
- Логирование в stdout для просмотра в Actions.

## 10. Тестирование

`pytest`, зависимости только stdlib + requests (если требуется — тестовые фикстуры
моковые).

- Модульные тесты математики: веса (обратная зависимость от MAE), среднее, медиана,
  круговое среднее ветра, голосование weather_code, NaN-пропуски, порог < 3 источников.
- Интеграционный тест (отдельная маркировка, запускается вручную/локально): реальный
  запрос Open-Meteo для Ярославля по всем моделям из `MODELS`, проверка структуры ответа.

## 11. Ограничения и не-цели

- Не-цель: несколько городов, карта, история/архив, база данных, личный кабинет,
  коммерческие API.
- Ограничения: точность весов ограничена 30-дневным окном; вкладка сравнения
  показывает только модели, покрывающие Ярославль; обновление — раз в час (не realtime).
- `weather_code` консенсус — приблизительный (голосование большинства).
