# Бот автообновления версий для samlab.ws

Дата: 2026-10-05

## Задача

Сайт samlab.ws хранит каталог программ в виде плоских файлов `soft/<slug>.ini`
(920 файлов). Сейчас обновления вносятся вручную: правится `.ini`, файл
заливается на сервер. Нужен бот, который раз в 6 часов сам проверяет источник,
находит новые версии и правит соответствующие `.ini` на месте.

Первый источник — RSS-фид раздела «Софтуер» на kaldata.com.

## Устройство сайта (контекст)

Сайт — самописный PHP-фронтконтроллер поверх плоских файлов, без БД.

- Роутинг: `/soft/<slug>/` → `index.php?act=full&prog=<slug>` (см. `.htaccess`)
- `index.php` подключает `act_<name>.php`, затем `templates/main.tpl`,
  который делает `require($include_name.'.tpl')`
- Шаблоны — обычные PHP-инклуды, шаблонизатора нет
- Контент программы — INI-секции: `[info]` (name, site, licence, type, size),
  секции `[link_N]` со ссылками, `[warez_best]`
- Тексты программы лежат отдельно в `.short` и `.long`
- Кодировка всех `.ini` — **windows-1251** (проверено: при декодировании
  `aimp.ini` в UTF-8 получается 69 битых байт, в cp1251 — ноль)

## Ключевые находки при обследовании

Эти находки определили дизайн и должны быть зафиксированы.

**1. Версия есть в URL только у 33% файлов.** Из 920 `.ini` с ссылками
версия прямо в URL встречается у 302 (33%). У остальных 585 (64%) ссылка
либо вечная (`.../installers/ChromeStandaloneSetup64.exe`), либо ведёт на
трекер со случайным именем (`turbobit.net/0bu8u10x42j8/...`), либо использует
собственный формат версии (`acdsee-photo-studio-home-2027-0-0-3620-win-en.exe`).

**2. Секции `[link1]` без подчёркивания — это резерв, не баг.** Их находят
346 файлов. `full.tpl` выбирает только `~^link_~`, поэтому такие ссылки не
выводятся на сайте намеренно: они сохранены на будущее. **Бот их не трогает
и не переименовывает.** Работаем только с `link_N` (с подчёркиванием).

**3. Сопоставление с kaldata решаемо, но не идеально.** Из 50 записей в
фиде автоматически матчатся 19: 10 по slug из URL (`reaper-51261` → `reaper`)
и 9 по нормализованному имени (`Mozilla Thunderbird` → `thunderbird`).
Остальные 31 — либо отсутствуют в каталоге (RustDesk, Spotify, Python),
 либо переименованы (`FL Studio` → `fruityloops`, `Malwarebytes` →
`antimalwarem`). Для известных расхождений — файл алиасов.

**4. kaldata отдаёт RSS, а WP REST API закрыт (403).** Фид раздела доступен
без авторизации и содержит 50 последних записей с заголовками вида
`REAPER 7.82 Final`. HTML-страницы отдаются только с UA браузера, часть
запросов возвращает пустой ответ — нужна защита от этого.

**5. Dev/Beta и Final обновляются независимо.** В `vivaldi.ini` имя
`Vivaldi 8.3.4175.3 Dev + 8.2.4133.83 Final`, в `firefox.ini` —
`Mozilla Firefox 158.0 Beta 3` плюс отдельная ссылка на 157.0. Числовое
сравнение по одному числу здесь бессмысленно. kaldata не публикует Dev.

## Решение: двухуровневый подход (вариант C)

Рассмотрены три варианта:

- **A. Заменить ссылки на ссылки kaldata.** Покрытие 100%, но ссылки kaldata
  ведут на их зеркала и рекламные переходы, а не на официальные сайты. Для 64%
  записей это смена официальной ссылки на стороннюю, что противоречит политике
  сайта. Плюс ~900 HTML-запросов за прогон.
- **B. Подстановка версии внутрь существующих URL.** Работает для 33%, ноль
  лишних запросов, ссылки остаются официальными. Покрытие мало.
- **C. Двухуровневый (выбран).** Ядро — как в B: точечная подстановка версии
  внутрь наших URL, хост и путь не трогаем. Для остальных 64% бот кладёт запись
  в очередь на ручную доработку, а URL с kaldata достаёт **только чтобы
  показать в этой очереди** — в `.ini` они не попадают ни при каких условиях.
  Так через пару недель видно, для каких программ стоит дописать правило.

Избран C. Принцип: то, что нельзя сделать надёжно, не делается молча, а
попадает в список на ручное решение.

## Расположение

Бот кладётся **вне веб-корня**, чтобы не был доступен из интернета.
Правит `soft/` на месте — FTP не нужен, права на запись есть.

```
/home/<user>/samlab-bot/
  run.py              точка входа
  kaldata.py          fetch: RSS + разбор страницы для очереди
  match.py            сопоставление с нашими .ini
  version.py          разбор и сравнение версий, каналы Final/Beta
  rewrite.py          подстановка версии в URL, запись .ini в cp1251
  config.json         путь к soft/, путь к aliases.json и state.json
  aliases.json        ручные соответствия: "FL Studio" -> "fruityloops"
  state.json          уже обработанные записи (по ссылке kaldata)
  bot.log             журнал за все запуски
  needs-review.txt    очередь на ручную доработку
```

Резервной копии подлежат `state.json` и `needs-review.txt`. `bot.log`
можно обрезать по дате.

## Поток одного запуска

Шесть шагов. Каждый может завершиться, ничего не изменив.

### 1. Fetch

Забрать RSS фида раздела kaldata. Одна сетевая ошибка — запуск просто
повторится через 6 часов, состояние не изменится. Свежие записи берутся из
`state.json`, остальные отбрасываются — иначе все 50 разбирались бы заново
каждый запуск.

### 2. Match

Для каждой записи найти наш `.ini`, по порядку попыток:

1. slug из URL kaldata (`reaper-51261` → `reaper`) сверяется с именами файлов;
2. если не нашлось — нормализованное имя из заголовка
   (`Mozilla Thunderbird 157.0.1 Final` → `mozillathunderbird`) ищется как
   вхождение в имена файлов, либо наоборот;
3. `aliases.json` — ручные соответствия для известных расхождений;
4. если не нашлось — запись в лог «не опознано», сайт не трогаем.

Нормализация: убрать хвостовые слова канала (`Final`, `Beta`, `Alpha`, `RC`,
`Dev`, `Stable`, `Portable`, `Enterprise`), оставить только буквы и цифры,
привести к нижнему регистру. Сравнение по вхождению требует длину обеих
сторон не менее 5 символов.

### 3. Compare

Извлечь версию и канал из заголовка kaldata, распарсить версию из нашего
имени.

**Разбор версии.** Первый числовой кластер разбирается на части и сравнивается
как кортеж чисел: `7.82` → `(7, 82)`, `8.2.4133.83` → `(8, 2, 4133, 83)`.
Сравнение числовое, поэтому `10.0 > 9.9` корректно.

**Каналы.** Метка в конце заголовка определяет трек: `Final`, `Stable` или
отсутствие метки → Final; `Beta N`, `Alpha`, `RC`, `Dev` → Beta.
Обновляется **только Final-трек**. Dev-часть нашего имени не трогается.

**Стоп-условия.** Запись пропускается, если:

- новая Final-версия ≤ нашей Final-версии (откат или то же самое);
- заголовок содержит `/` с двумя версиями (`Advanced Renamer 4.27 / 3.95 Final`) —
  непонятно, какая главная;
- версия не распозналась — нет ни одного числа;
- заголовок содержит `Crack`, `Keygen`, `REPACK` — не наш контент по политике сайта.

**Сложные имена.** `PotPlayer SamLab Edition 26.10.2 Beta - SamLab.ws сборка!`
бот не пересобирает целиком. Он заменяет ровно один числовой кластер — тот,
что стоит в позиции Final-трека. Хвост после версии сохраняется как был.
Бот меняет цифры, а не сочиняет названия заново.

### 4. Rewrite-ссылок (ядро)

Бот знает старую версию (из нашего имени) и новую (из kaldata) и подставляет
новую внутрь наших URL, не меняя хост и путь:

```
наш:     https://www.reaper.fm/files/7.x/reaper782-install.exe
kaldata:  7.82  →  7.83
станет:  https://www.reaper.fm/files/7.x/reaper783-install.exe
```

Поддерживаемые формы записи версии в URL:

- точная — `8.2.4133.83`;
- компактная без разделителей — `reaper782` (из `7.82`);
- с другими разделителями — `8-2-4133-83`.

Подстановка должна быть однозначной: если старая версия встречается в URL
несколько способов или не встречается ни разу — подстановка считается
неудачной.

**Если ни одна ссылка не поддалась подстановке — бот ничего не пишет в файл**
и кладёт запись в `needs-review.txt`.

### 5. Отложенная проверка

Для записей, попавших в очередь, бот скачивает HTML-страницу kaldata,
вытаскивает прямые URL (`https?://\S+\.(exe|msi|zip|7z|rar|dmg|tgz|deb)`)
и сохраняет их **только в отчёт**, не записывая в `.ini`:

```
REAPER: новая 7.83, наши ссылки вечные — нечего подставлять.
  kaldata предлагает: https://dlcf.reaper.fm/7.x/reaper783-install.exe
  наш файл: soft/reaper.ini
```

Смысл: через пару недель видно, для каких программ это стоит включить, и
правила дописываются вручную — осознанно и поштучно.

Скачивание страниц — **только для записей из очереди**, не для всех.

### 6. Commit

Порядок для каждого изменённого файла:

1. копия в `<файл>.ini.bak`;
2. запись во временный файл в кодировке cp1251;
3. атомарное переименование — читатели сайта никогда не увидят половину файла.

Запись — **точечная**, а не пересборка файла: правится версия в строке `name=`
и значения `link=` внутри секций `link_N`. Всё остальное сохраняется байт в
байт: `\r\n`, порядок секций, кавычки, пробелы, секции `[warez_best]`,
секции `[link1]` без подчёркивания.

## Режимы запуска

**По умолчанию — `--dry-run`:** бот формирует полный отчёт и ничего не пишет
ни в один `.ini`. Реальная запись — только по явному `--apply`.

Это значит, что cron изначально настраивается с `--dry-run`; для перехода на
автоматическую запись достаточно поменять команду в панели хостинга.

Cron: `0 */6 * * *`, команда вида
`cd /home/<user>/samlab-bot && python3 run.py >> cron.log 2>&1`.
Первое расписание — с `--dry-run`.

## Отчёт

Каждая запись завершается одним из исходов:

- обновлено;
- версия kaldata не новее нашей;
- не опознано (не нашли `.ini`);
- подстановка не удалась → в очередь;
- откат;
- пропущено по правилу (`/`, Crack/Keygen/REPACK, версия не распозналась).

Пишется в `bot.log`; записи из очереди — в `needs-review.txt`.

## Тесты

Логика версий, сопоставления и подстановки — чистые функции, тестируются без
сети и без реальных файлов.

**`version.py`**
- разбор: `7.82`, `8.2.4133.83`, `3.0.6741`, `158.0 Beta 3`, мусорные строки;
- сравнение: `7.83 > 7.82`, `10.0 > 9.9`, равные, откат;
- каналы: `Final` → Final, `Beta 7` → Beta, без метки → Final.

**`rewrite.py`**
- подстановка: точная форма, компактная `reaper782`, разделители `8-2-4133-83`;
- отказ: версии нет в URL, неоднозначное совпадение, версия короче 3 символов
  в компактной форме;
- запись: содержимое не изменилось побайтово, когда обновлять нечего;
  после подстановки отличается только версия; кириллица не рассыпалась;
  секции `[link1]` без подчёркивания остались нетронутыми.

**`match.py`**
- совпадение по slug, по нормализованному имени, по алиасу;
- промах; слишком короткие строки отбрасываются.

**Живой тест на копии**
- взять реальные `.ini` (REAPER, Vivaldi, Firefox, Chrome), применить
  подставленную вручную новую версию, сверить результат с ожидаемым,
  убедиться, что файл открывается `parse_ini_file`.

## Чего бот не делает

- Не сканирует всё подряд — только RSS за последние сутки.
- Не лезет в HTML kaldata для всех записей — только для очереди.
- Не трогает секции `[linkN]` без подчёркивания, `[warez_best]`, `.short`,
  `.long`, скриншоты.
- Не откатывает версии.
- Не деплоит по FTP — правит файлы на месте.
- Не трогает Dev/Beta-трек (пока нет источника).
- Не переименовывает `link1` в `link_1`.

## Границы задачи

Первая версия работает с одним источником — kaldata. Архитектура это
допускает: добавление источника = новый модуль-фетчер плюс запись в
`config.json`. Dev/Beta-трек заведён в модели данных, но не наполняется:
для него нужен отдельный источник, и это отдельная задача.

Ручные правила подстановки для конкретных программ — по мере накопления
очереди, вручную, по одному.
